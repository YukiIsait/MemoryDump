# MemoryDump

🌍 **[English](README.md) | [简体中文](README-CN.md)**

一个轻量级的 Windows 命令行工具，用于从正在运行的进程中按 PID 或可执行文件名转储内存区域。

## 功能

- 通过 **PID**（`-p`）或 **可执行文件名**（`-n`）指定目标进程
- 支持两种方式指定内存范围：
  - 起始地址 + 长度（`-a` + `-l`）
  - 起始地址 + 结束地址（`-a` + `-e`）
- 支持 **十六进制**（如 `0x1000`）和 **十进制** 输入
- 输出为二进制文件（`-o`）

## 用法

用法: memdump [选项]

| 选项 | 描述 |
| -- | -- |
| `-p PID` | 通过 PID 指定目标进程（整数） |
| `-n 进程名称` | 通过进程名称指定目标进程（例如 notepad.exe） |
| `-a 起始地址` | 内存起始地址（十六进制或十进制，例如 0x1000 或 4096） |
| `-e 结束地址` | 内存结束地址（不包含该地址，十六进制或十进制） |
| `-l 长度` | 要转储的字节数（十六进制或十进制） |
| `-o 输出文件` | 输出的转储文件路径 |

## 示例

```shell
# 从 notepad.exe 转储从 0x1000 开始的 0x500 字节
memdump -n notepad.exe -a 0x1000 -l 0x500 -o dump.bin

# 使用 PID 和十进制数值
memdump -p 23324 -a 4096 -l 1280 -o dump.bin

# 转储从 0x1000 到 0x1500 (不包含 0x1500) 的内存
memdump -p 23324 -a 0x1000 -e 0x1500 -o dump.bin

# 混合使用十六进制和十进制
memdump -p 12345 -a 0x7FF00000 -l 4096 -o region.bin
```

> 注意：使用 `-e END_ADDR` 时，该地址是不包含的 - 即 `END_ADDR` 对应的字节不会被写入转储文件。
